Aperçu

Un tableau de bord complet pour suivre les horaires de tramway en temps réel.

L'application interroge l'API SIRI 2.0 de la CTS et diffuse les données en direct vers tous les navigateurs connectés via WebSocket. Un seul binaire auto-contenu sert à la fois l'interface web et l'API REST.

🔴

Temps réel confirmé GPS

Les horaires en gras sont confirmés par GPS. Les horaires en italique sont théoriques (grille horaire).

🔄

Rotation multi-arrêts

Surveillez plusieurs codes d'arrêt simultanément. Le tableau défile automatiquement entre les arrêts.

📱

Responsive & tactile

Disposition compacte sur mobile (≤ 480 px). Glissement gauche/droite pour changer d'arrêt manuellement.

⛅

Météo intégrée

Bandeau météo en bas du tableau : température min/max, précipitations, indice UV. Fond animé (pluie, neige, soleil…).

🎂

Anniversaires du jour

Affiche les anniversaires depuis un fichier JSON de contacts, avec calcul automatique de l'âge.

📅

Compteur Jour J

Défilement des prochains événements avec icône, label et décompte en jours. Animation confettis le jour J.

💡

Écran LED Pixoo64

Affichage Ambient Hub sur une matrice LED 64×64 Divoom Pixoo64, avec horloge et bandes colorées par ligne.

📦

Binaire unique

L'interface web est intégrée à la compilation. Déployez avec un simple scp, aucune dépendance externe.

Installation

Compilez depuis les sources ou déployez le binaire pré-compilé.

Prérequis

  • Rust 1.75+ (utilise async fn dans les traits via AFIT)
  • Un jeton API CTS Open Data — gratuit, à demander sur cts-strasbourg.eu
  • Facultatif — Clé API Meteoblue pour la météo
  • Facultatif — Un appareil Divoom Pixoo64 pour l'affichage LED

Compilation native (Linux aarch64)

# Build de développement
cargo build

# Build de production optimisé (LTO activé)
cargo build --release
# ou via le script fourni :
./build_release.sh

Cross-compilation depuis macOS (M1/M2/M3) → Freebox Delta

Bien que Mac et Freebox soient tous deux ARM64, le Mac produit un binaire Mach-O (macOS) tandis que la Freebox attend un ELF Linux. La solution est cargo-zigbuild : Zig embarque un cross-compilateur — aucun Docker requis.

1
Configuration unique 
cargo install cargo-zigbuild
rustup target add aarch64-unknown-linux-musl
2
Compiler et déployer 
./build_freebox.sh

Produit un ELF statique (~3,4 Mo) dans dist-freebox/ et le copie automatiquement sur les instances via scp.

3
Lancer le serveur 
# Avec la configuration par défaut
cargo run --release

# Avec un fichier de configuration personnalisé
cargo run --release -- /chemin/vers/config.toml

Puis ouvrir http://localhost:3000 dans votre navigateur.

💡

Pourquoi musl et non gnu ? musl produit un binaire entièrement statique, sans dépendance à la version glibc de la Freebox. Déploiement simplifié, zéro surprise « mauvaise glibc ».

Mode démo (sans clés API)

CTS et météo peuvent être simulés indépendamment. Utilisez demo.toml pour un démo entièrement autonome :

cargo run -- demo.toml

La démo active des départs CTS simulés, une météo simulée, les anniversaires et le compteur Jour J. Les horaires sont légèrement jittérisés à chaque cycle pour donner une impression de vivant.

Configuration

Copiez et éditez config.toml. Toutes les clés CTS sont préfixées cts_, météo meteoblue_, écran LED pixoo64_.

Configuration CTS

# ── API CTS ───────────────────────────────────────────────────────────────────

# Votre jeton API CTS Open Data
cts_api_token = "xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx"

# Codes d'arrêt à surveiller — tableau TOML inline.
# Ajoutez plusieurs entrées pour tourner automatiquement entre les arrêts.
# Exemples : "233A" = Homme de Fer,  "298B" = Jean Jaurès (dir. Gare Centrale)
cts_monitoring_ref = ["298B"]

# Durée d'affichage de chaque arrêt en secondes (multi-arrêt uniquement)
cts_stop_rotation_in_second = 15

# Fréquence d'interrogation de l'API en minutes
cts_polling_interval_minutes = 2

# Nombre maximum de prochains départs demandés par appel API
cts_max_stop_visits = 10

# Adresse du serveur web (0.0.0.0 pour écouter sur toutes les interfaces)
listen_addr = "0.0.0.0:3000"

# Simulation CTS (données fictives, aucune clé nécessaire)
cts_simulation = false

Fenêtres d'interrogation (style crontab)

Restreignez les appels API aux plages horaires de service grâce à des expressions crontab à 5 champs. Les points-virgules séparent plusieurs clauses ; l'interrogation a lieu dès qu'une clause correspond. 

# Interrogation uniquement pendant les heures de service :
#   Semaine 6h–23h, week-end 8h–23h :
cts_always_query = false
cts_query_intervals = "* 6-23 * * 1-5; * 8-23 * * 0,6"

# Matin + après-midi + soir :
# cts_query_intervals = "* 6-9,14-18,22-23 * * *"

meteoblue_enabled                   = true

meteoblue_location                  = "Strasbourg"

meteoblue_simulation                = false

Écran LED Pixoo64 (facultatif)

Anniversaires (facultatif)

birthday_enabled = true
birthday_file    = "data/birthdays.json"

Format du fichier JSON :

{
  "birthdays": [
    { "name": "Jean Martin",   "date": "12/04"       },
    { "name": "Claire Dupont", "date": "03/07/1985" }
  ]
}

Format de date : JJ/MM (annuel, sans année) ou JJ/MM/AAAA (âge calculé et affiché automatiquement).

Tour d'horizon des principales fonctions de l'application.

Statut système

Cliquez sur le point de statut (●) dans l'en-tête pour ouvrir l'overlay de statut. Il présente deux onglets :

  • Météoblue — nom de lieu résolu, coordonnées, dernier fetch, valeurs météo actuelles, état des fenêtres d'interrogation.

Sélecteur d'arrêt — parcourez tous les arrêts CTS et changez l'arrêt surveillé à la volée. La modification est sauvegardée dans config.toml et un nouveau poll est déclenché immédiatement. La liste des arrêts est récupérée depuis l'API CTS réelle, même en mode simulation.

Widget météo

Quand meteoblue_enabled = true, le bas du tableau affiche une bande météo en direct : 

☁  7°C / 19°C  💧 2.5 mm  UV 3
  • Le nom de ville (meteoblue_location) est résolu en coordonnées via l'API Meteoblue au démarrage.
  • Un fond animé s'affiche derrière la bande : gouttes de pluie, flocons de neige, nuages, soleil, éclairs… selon le pictocode Meteoblue courant.
  • Quand le tableau est chargé et l'espace réduit, la bande météo se réduit gracieusement — les lignes de départ ont toujours la priorité.

Anniversaires du jour

Quand birthday_enabled = true et que moins de 4 lignes de départ sont affichées, les anniversaires du jour s'affichent en défilement horizontal. L'âge est calculé automatiquement si l'année de naissance est renseignée.

Compteur Jour J

Quand jour_j_enabled = true, une banderole défilante liste tous les événements à venir avec leur icône, leur libellé et le nombre de jours restants.

  • Les anniversaires proches (dans birthday_days_ahead jours) sont automatiquement fusionnés dans le défilement Jour J.
  • Les événements du jour J font clignoter leur badge en or avec une animation confettis.
  • Gérez les événements à la volée via Configuration → Jour J : ajout, suppression, réglage de l'horizon d'anniversaires.
  • Les événements passés sont élagués automatiquement à l'ouverture de la config.

Canvas arabesque

La zone vide sous la bande météo contient une animation ornementale lente : cinq designs d'arabesque SVG se dessinent progressivement (animation stroke-dashoffset), se maintiennent brièvement, puis s'effacent avant que le design suivant commence. Purement décoratif.

API REST & WebSocket

Tous les endpoints /api/* sont bloqués par nginx pour les clients externes (non-LAN) — ils renvoient 403 avant d'atteindre le serveur Rust.

EndpointDescription
GET /ws Flux WebSocket — pousse le JSON DepartureBoard à chaque mise à jour
GET /api/stops Liste tous les arrêts logiques (triés par nom)
GET /api/stops/:code/details Arrêts physiques et lignes/directions sous un code logique
POST /api/config {"monitoring_refs":["298B"]} — change les arrêts surveillés à chaud
POST /api/jour-j Met à jour les événements Jour J et l'horizon d'anniversaires
GET /api/status État du polling, statut météo, événements Jour J et config anniversaires
GET /api/pixoo64/preview Dernière frame Pixoo64 en PNG (mode simulation uniquement)

Rechargement à chaud via API

Les clés Pixoo64 qui supportent le rechargement à chaud peuvent être mises à jour sans redémarrage :

curl -X POST http://localhost:3000/api/config \
  -H "Content-Type: application/json" \
  -d '{"pixoo64_lines_per_screen": 2}'

La modification prend effet dès la prochaine frame rendue.

Sécurité & Déploiement

L'application est conçue pour être exposée sur internet via un reverse proxy nginx.

Contrôle d'accès géographique

nginx utilise un bloc geo pour classifier les requêtes en internes (LAN) ou externes. La variable $cts_is_external pilote toutes les décisions d'accès :

SurfaceInterne (LAN)Externe (internet)
Tableau de bord (WebSocket) Tableau complet avec anniversaires et Jour J Tableau livré, mais birthdays_today et jour_j_events sont supprimés côté serveur
/api/stops, /api/config, /api/jour-j, /api/status Autorisé Bloqué par nginx (403) — n'atteint jamais Rust
Boutons Config et Statut Visibles Masqués (UI uniquement — le blocage API est la vraie barrière)
Lignes Anniversaires / Jour J Visibles Masquées (JS) — données absentes du payload de toute façon
⚠️

Pourquoi supprimer côté serveur et pas seulement cacher en JS ? Le JavaScript exécuté dans le navigateur peut être modifié par n'importe qui. Masquer un élément UI n'empêche pas un attaquant de lire les frames WebSocket directement dans les DevTools. Le serveur maintient deux canaux de diffusion — un complet (interne), un filtré (externe) — et route chaque client WebSocket vers le canal approprié selon l'en-tête X-CTS-External positionné par nginx.

Limitation de débit

GET /api/stops et les endpoints de découverte d'arrêts sont limités à 10 requêtes/minute par IP (zone cts_stops dans nginx-conf.d-cts.conf).

Configuration multi-instances nginx

Le fichier dist/nginx-default couvre trois instances simultanées :

InstancePréfixe de cheminPort
Jaurès/cts/jaures/3000
Gallia/cts/gallia/3001
Porte Hop/cts/portehop/3002

Chaque instance possède ses propres blocs location WebSocket, API et assets statiques. Une page d'erreur partagée (dist/cts-offline.html) est servie lorsqu'un backend est indisponible.

Artefacts de déploiement

  • dist/nginx-conf.d-cts.conf → déployer dans /etc/nginx/conf.d/cts.conf
  • dist/nginx-default → déployer dans /etc/nginx/sites-enabled/default
  • dist/cts-offline.html → déployer dans /var/www/html/
